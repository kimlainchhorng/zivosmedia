### (2) BadgesPage.tsx — **1 edit (hybrid: className + aria-pressed, no ring)**

**Decision: option (b) — add `active:scale` + `aria-pressed`, skip ring, owner-flag keyboard gap.**

Rationale: `active:scale-[0.97]` provides real touch feedback for the dominant mobile audience — that's pure CSS, in scope. `aria-pressed` is a confirmed display-only attr. But `focus-visible:ring` is **dead CSS** without `tabIndex` — the Badge renders a `<div>` that can never receive keyboard focus, so the ring never triggers. Adding dead CSS is worse than omitting it (misleading audit trail). The owner-flag covers the real fix (`tabIndex={0}` + `role="button"` + `onKeyDown` + ring — logic, out of scope).

No missed controls. Stats Card, badge grid cards are `motion.div` with no `onClick`. All icons/`<Progress>`/`<Avatar>` non-interactive.

**L146 — shadcn `<Badge onClick>` filter:**

Before:
```
<Badge
  key={cat}
  variant={activeCategory === cat ? "default" : "outline"}
  className="cursor-pointer capitalize shrink-0"
  onClick={() => setActiveCategory(cat)}
>
```

After:
```
<Badge
  key={cat}
  variant={activeCategory === cat ? "default" : "outline"}
  aria-pressed={activeCategory === cat}
  className="cursor-pointer capitalize shrink-0 transition-all active:scale-[0.97]"
  onClick={() => setActiveCategory(cat)}
>
```

(shadcn Badge ships `transition-colors` internally; adding `transition-all` in the prop overrides it via CSS cascade — both set `transition-property`, `transition-all` wins — so the `active:scale` transform animates smoothly alongside the variant color swap. No ring — dead CSS.)
