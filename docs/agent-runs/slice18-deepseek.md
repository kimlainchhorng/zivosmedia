## (2) BadgesPage — DECISION: Pure flag (option a) ✅

**The shadcn `<Badge>` filter (~L146) renders as a `<div>` with `onClick` but no `tabIndex`/`role`/`onKeyDown`.**

**Recommendation: Pure owner-flag. Do NOT add tokens or aria-pressed.**

Rationale:
- `aria-pressed` on a `<div>` is technically valid ARIA (any element can have it), but it's **semantically misleading** without `role="button"` — screen readers won't announce it as a toggle button.
- `active:scale-[0.97]` would provide visual tap feedback, but adding it to a keyboard-inaccessible element is **half a fix** — the real gap is keyboard reachability, not visual polish.
- Adding `focus-visible:ring` without `tabIndex` is **dead CSS** (the element can never receive keyboard focus).
- The className-only mandate means we can't add `tabIndex={0}` + `role="button"` + `onKeyDown` — those are logic changes.

**Flag text for owner:**
> `BadgesPage` ~L146: The category filter uses `<Badge>` (renders `<div>`) with `onClick` but no `tabIndex={0}`, `role="button"`, or `onKeyDown` handler — keyboard-inaccessible. Fix: add `tabIndex={0}`, `role="button"`, `onKeyDown={(e) => e.key === 'Enter' && setActiveCategory(cat)}`. Once fixed, add `active:scale-[0.97]` + `focus-visible:ring-2 focus-visible:ring-ring` to the Badge's `className`.

**Missed anything?** No. Back Button (~L116) is shadcn → skip. Stats Card (~L123) + badge grid cards (~L177) are `motion.div` with no `onClick` → skip. No `<img>` tags. **0 edits.**
